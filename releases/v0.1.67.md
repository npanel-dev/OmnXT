# OmnXT Node v0.1.67

本版本更新 Node 与 CLI，程序版本均为 `0.1.67`。源码为
[`980139c32c0c6ba61fcbbff972b4603e47ead6dc`](https://github.com/SunGreatSage/OmnXT/commit/980139c32c0c6ba61fcbbff972b4603e47ead6dc)，分支为 `development`。

## 修复内容

- SimNet SDK 会话在上传写入受到背压时，仍能接收下行数据、处理消费返窗和控制帧。发送保持有界，容量统计覆盖待编码、已编码和部分写入数据；OPEN 完整写出后才完成，Ping 超时从完整提交开始计时。
- SimNet Node 不再等待某条流的满上传队列，避免一个慢目标阻塞同会话其他流与 Pong。上传按目标 TCP 实际接受字节返还信用，保留待交付 DATA 的预算与顺序；FIN、Reset、接收端退出及 GOAWAY 后的回收均有回归。
- ClientOpen 通告客户端实际接收窗口，覆盖非对称窗口、AF 抖动、旧合同与恢复；StreamOpen 的既有合同保持。
- 包含上版发布后提交的 VLESS/REALITY 修复：完整处理 REALITY 记录及首批缓冲写入。

默认 H2/逻辑窗口、并发容量、AF 配置及 Release 优化参数保持原值。

沿用 v0.1.66 的双架构 GNU Linux 产物合同，本地构建并发布四个附件：


实际二进制和归档 SHA256、GLIBC 需求、构建身份及产物验证记录见 [发布清单](https://github.com/npanel-dev/OmnXT/blob/main/releases/v0.1.67.json)。

## 验证结果与限制

SimNet/proxy-stream 相关测试 421 项通过、12 项既有忽略，格式与 workspace 编译检查通过。旧实现的窗口方向、Node 阻塞上传和 SDK H2 回压问题已有失败复现及修复后通过记录；版本同步后再次通过 workspace 检查。发布产物另核对两架构 ELF、GLIBC 需求、程序版本、源码 revision、CLI 配置与有限 Node 启动。

相同依赖、编译参数及默认配置的真实 SDK + Node + TLS/H2/AF Release 对照，本地下载中位差异在 ±1% 内，上传未见下降；所有传输完整性校验通过。100Mbps、200ms RTT 合成链路五组交错对照，下载中位数 87.27→88.14Mbps，小请求中位数 356.9→384.7ms，最大约 1.34s。保留这项延迟疑点，不承诺高 Ping 已全部修复，也不能认定客户约 40Mbps 的全部原因已消除。

## 升级说明

本轮 Node 上传队列与生命周期修复需要升级 Node。完整 SimNet 修复还需要客户端采用从同一源码构建的新 SDK；本次附件交付 Node/CLI，未重新交付平台 SDK。本次发布没有升级或重启客户服务器，客户设备及真实链路复测仍待完成。

安装指定版本：

```bash
curl -fsSL https://raw.githubusercontent.com/npanel-dev/OmnXT/main/install.sh | sudo bash -s -- 0.1.67
```

下载归档后，在同一目录手动校验：

```bash
sha256sum -c omnxt-node-x86_64-unknown-linux-gnu.tar.gz.sha256
```

ARM64 替换为对应 `.sha256` 文件名。现有安装脚本没有自动执行该校验。
